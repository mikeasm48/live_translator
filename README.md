# Live Translator

Живой перевод речи: микрофон (или звук созвона) → **Gemini**, который слышит
узбекскую речь и сразу отвечает по-русски → текст в окне поверх всех окон,
в терминале и в файле.

Прежняя связка Yandex — SpeechKit STT v3 плюс YandexGPT — осталась и включается
одной настройкой. Почему переехали на Gemini, с цифрами, — в разделе «Чем
слушать речь». Java 21.

---

## 0. Установка

```bash
brew trust mikeasm48/tap
brew install mikeasm48/tap/live-translator
```

Первая команда нужна один раз: Homebrew требует явно доверять сторонним
источникам формул.

Запустите один раз `live-translator` — приложение добавит себя в «Программы»
и дальше будет открываться двойным щелчком из Launchpad, Finder и Spotlight.

Сделать это при установке нельзя: Homebrew ставит формулы в песочнице с
подменённым домашним каталогом, а общий `/Applications` защищён механизмом
App Management и без разрешения туда не пускает.

Java подтянется сама как зависимость — ставить её отдельно не нужно.

Обновление: `brew upgrade live-translator`. Удаление: `brew uninstall live-translator`.

Установленное приложение держит настройки и словарь терминов в
`~/.config/live-translator/`, а расшифровки встреч и записи звука —
в `~/Documents/LiveTranslator/`.

### Из исходников

```bash
git clone git@github.com:mikeasm48/live_translator.git
cd live_translator
mvn package
./run.sh
```

Нужны Java 21+ и Maven. Запуск из папки с исходниками держит настройки в `.env`,
логи в `./logs` — чтобы разработка не мешалась с установленной копией.

При первом запуске приложение само спросит идентификатор
каталога и API-ключ: ключ уйдёт в связку ключей macOS, в `.env` останется только
команда его чтения. Файл `.env` создаётся автоматически и в репозиторий не попадает.

Для звука из созвонов понадобится BlackHole — инструкция встроена в приложение:
**Cmd + ,** → вкладка «Звук из созвона».

Всё остальное имеет разумные умолчания: языки `uz-UZ, ru-RU, en-US`, источник
звука BlackHole, перевод на русский. Меняется в настройках и запоминается.

## 1. Что нужно в Yandex Cloud

1. Создать каталог (folder) — его идентификатор понадобится, он виден в консоли
   в адресе `console.yandex.cloud/folders/<folder-id>`.
2. Создать сервисный аккаунт и выдать ему роли:
   - `ai.speechkit-stt.user` — распознавание речи;
   - `ai.translate.user` — перевод.
3. Создать для него **API-ключ** (не статический ключ доступа, а именно API-key).

Проще всего не заполнять `.env` руками: запустите приложение, и оно спросит
недостающее само. Ниже — что именно оно сохраняет и как это поправить вручную.

### Куда положить ключ, чтобы не вводить его каждый раз

```bash
cp .env.example .env && chmod 600 .env
```

Дальше вписать в `.env` свои значения:

```
YC_FOLDER_ID=b1g...
YC_API_KEY=AQVN...
LT_DEVICE=BlackHole
```

`LT_DEVICE` — источник звука по умолчанию, подстрока имени устройства. Аргумент
`--device` главнее, так что разовый запуск с другим источником по-прежнему
работает: `./run.sh --device=Микрофон`.

Файл в `.gitignore`, в репозиторий не попадёт. Если копий проекта несколько,
те же строки можно положить в `~/.config/live-translator/config` — он общий.

**Надёжнее: ключ в Keychain, а не в файле.** Один раз положить:

```bash
security add-generic-password -a "$USER" -s live-translator -w
```

(команда спросит ключ и не покажет его на экране), и вместо `YC_API_KEY`
написать в `.env`:

```
YC_API_KEY_CMD=security find-generic-password -s live-translator -w
```

Приложение выполнит команду и возьмёт её вывод. На диске остаётся только
команда, сам секрет — в Keychain.

Порядок поиска значения: переменная окружения → `./.env` →
`~/.config/live-translator/config` → команда `<ИМЯ>_CMD`. Переменная окружения
главнее всего, так что разовый запуск с другим ключом по-прежнему работает:
`YC_FOLDER_ID=b1other java -jar ...`

Вместо API-ключа можно использовать IAM-токен (`YC_IAM_TOKEN`), но он живёт
12 часов и для постоянной работы неудобен.

## 2. Сборка

```bash
mvn package
```

Получится `target/live-translator.jar` — самодостаточный, со всеми зависимостями.

## 3. Обновление

Приложение проверяет при запуске, не вышла ли версия новее, и предлагает
обновиться само: кнопка «Обновить», минута ожидания, перезапуск. В терминал
ходить не нужно.

Проверка не задерживает запуск: если сеть не отвечает за пять секунд, приложение
просто работает дальше. Отключается настройкой `LT_CHECK_UPDATES=false`.

Вручную, если так привычнее:

```bash
brew update && brew upgrade live-translator
```

## 4. Проверка связки без микрофона

```bash
live-translator --selftest
```

Проверяется тот движок, который выбран. Для Gemini: разрешается ли имя сервиса,
принят ли ключ, за сколько отвечает модель. Секунда тишины стоит долей копейки.

Делать это стоит **перед встречей и в той же сети**, в которой будете работать.
Корпоративный VPN умеет подсовывать нерабочий сервер имён, и тогда приложение не
достучится до модели — выясняется это обычно в ту минуту, когда все уже
собрались. Если имя не разрешается, проверьте:

```bash
nslookup generativelanguage.googleapis.com
```

и при необходимости пропишите рабочие серверы имён:

```bash
sudo networksetup -setdnsservers Wi-Fi 1.1.1.1 8.8.8.8
```

## 5. Запуск

```bash
java -jar target/live-translator.jar
```

Откроется окно поверх всех окон с бегущим переводом; то же самое дублируется в
терминал и пишется в `logs/session-<дата>.md` (перевод + оригинал под ним).

Кнопка **⏸ пауза** в панели останавливает перевод, не закрывая приложение:
поток к облаку закрывается, звук никуда не уходит, расход денег прекращается.
Повторное нажатие продолжает работу.

Полезные аргументы:

| Аргумент | Что делает |
|---|---|
| `--list-devices` | показать устройства записи |
| `--device=BlackHole` | выбрать устройство по подстроке имени |
| `--level` | шкала уровня звука с устройства, без обращений в облако |
| `--record` | писать звук в WAV с самого старта |
| `--try="фраза"` | перевести фразу без словаря и со словарём |
| `--no-ui` | без окна, только терминал |
| `--no-translate` | только расшифровка на узбекском |
| `--glossary=путь` | другой файл словаря (по умолчанию `./glossary.txt`) |
| `--lang=uz-UZ,ru-RU,en-US` | языки распознавания через запятую, либо `auto` |
| `--target=ru` | язык перевода |
| `--pause=600` | пауза (мс), после которой фраза считается законченной |
| `--eou-default` | реже резать фразы — для речи с чёткими паузами |
| `--no-literature` | отключить литературную нормализацию |
| `--vad-threshold=180` | фиксированный порог тишины вместо автоподбора |
| `--no-vad` | слать в облако всё подряд, включая тишину |
| `--font-size=24` | крупнее шрифт в окне |

Выход — `Ctrl+C`.

## 6. Звук из созвона (Zoom / Meet / Teams) на macOS

Микрофон слышит только вас и комнату. Чтобы распознавать собеседника в звонке,
нужен виртуальный аудиокабель:

1. Установить [BlackHole](https://github.com/ExistentialAudio/BlackHole):
   `brew install blackhole-2ch`
2. В «Настройка Audio-MIDI» создать **Multi-Output Device** из ваших наушников
   и BlackHole 2ch — чтобы звук звонка шёл и в уши, и в кабель.
3. Выбрать этот Multi-Output как устройство вывода системы (или только в Zoom).
4. Запустить: `java -jar target/live-translator.jar --device=BlackHole`

При первом запуске macOS спросит разрешение на доступ к микрофону для терминала —
без него `TargetDataLine` отдаёт тишину.

## 7. Чем слушать речь: Gemini или Yandex

По умолчанию работает **Gemini**: модель слушает звук и сразу отвечает
по-русски, без отдельного распознавания и отдельного перевода.

Так сделано по результатам замера на узбекской записи рабочего урока. Yandex не
узнал ни одного технического термина из пяти и выдавал фонетически похожий
мусор — «IntelliJ IDEA» превращалась в «intervyu ideya», а целые куски уходили
в несуществующий английский. Gemini узнал все пять. Причина в устройстве: схема
«звук → текст → перевод» необратимо теряет акустику на средней стрелке, и
дальше по цепочке искажённое название можно только угадать по смыслу соседних
слов. Модель, которая слышит сама, этого шага не делает.

Yandex остаётся на месте и включается в настройках или ключом
`--engine=yandex`.

### Как это работает

Звук копится в кусок и уходит модели целиком. Кусок закрывается **на ближайшей
паузе в речи** после половины отведённого срока, а если пауз не случилось — по
жёсткому пределу (10 или 20 секунд, выбирается в настройках).

Пауза здесь важнее предела. Резать ровно на десятой секунде значит регулярно
разрывать фразу посередине: модель получит огрызок без конца, а конец без
начала, и переведёт неверно оба. И второе, что важнее первого: если кусок
закрывается тогда же, когда человек замолчал, ждать остаётся только обработку,
а не всю длину куска сверху.

### Приложение начинает работу на паузе

Это намеренно. Окно открывают заранее, до начала встречи, и всё это время
микрофон слушает тишину — а в тишине модель принимается выдумывать (см. ниже).
Поэтому перевод включается кнопкой **«▶ продолжить»** в панели, когда встреча
действительно началась.

### Тишину модели не показывают

Это важно знать про мультимодальные модели вообще. На записи без речи Gemini не
молчит: в лучшем случае просит прислать запись, в худшем — **выдумывает**
правдоподобную встречу. Проверено на тридцати секундах комнатного шума: модель
сочинила стендап с Jira, Docker и обсуждением API, на двух языках, неотличимо
от настоящего перевода.

Правилами в задании это не лечится: запрет выдумывать модель понимает по-своему.
Поэтому защита стоит раньше — кусок не отправляется, пока в нём не наберётся
хотя бы 0,7 секунды именно речи, а не шума. Проверяет это детектор речи, тот же,
что отсеивает паузы. На тридцати секундах тишины приложение не делает ни одного
запроса.

Вторым рубежом стоит фильтр: если модель всё же заговорила с нами вместо
перевода, такая строка в окно и в расшифровку не попадает.

Остаётся случай, от которого защиты нет: если в куске есть немного настоящей
речи и много шума, модель может дополнить услышанное правдоподобным. Это
свойство таких моделей, а не ошибка настройки, и знать о нём стоит.

Подозрение, что выдумку подкармливает наш же промпт, подтвердилось. В логах с
целевой машины сочинённый стендап состоял **целиком из словаря**: Docker, Spring
Boot, Kafka, Maven, Jira, Kubernetes, commit, merge, rollback и даже узбекские
пары `muhit` и `ishlab chiqarish`. Замер на той же тишине: со словарём 15 строк
выдумки, без словаря 5.

Виноват был не только словарь. В задании стояло «это рабочая встреча команды
разработчиков» — готовая декорация, в которую модель и расставляла термины.
Фраза убрана: теперь задание нейтральное, «ты синхронный переводчик», без
предположений о том, кто и о чём говорит. Список терминов подаётся условно
(«если встретятся эти названия») вместо предсказания («скорее всего,
прозвучат»).

После этого на той же тишине осталось три строки общей болтовни вместо
пятнадцати строк правдоподобного совещания. Выдумка не исчезла, но стала
заметной — а это разница между «странно» и «не отличить».

Время у каждой реплики — то, когда её произнесли, а не когда пришёл ответ.
Модель размечает реплики внутри куска, и без этого все фразы одного куска
получали бы одну метку, хотя между первой и последней прошло десять секунд.

Реплика, оборванная границей куска, дописывается продолжением из следующего:
человеку нужна целая фраза, а не три обрывка с отметками времени. Признак
обрыва — реплика не кончилась знаком конца предложения. Наращивание ограничено
тремя кусками: знак конца модель ставит не всегда, и без предела одна строка
росла бы всю встречу.

Звук перед отправкой сжимается в AAC 32 кбит/с. На счёт это не влияет —
секунда стоит 32 токена в любом формате, — но десять секунд сырого звука это
417 КБ запроса против 60 КБ сжатого. На домашнем канале разница теряется в
шуме; на гостиничном wi-fi в мегабит сырой кусок уезжал бы 3,3 секунды, то есть
дольше, чем копится следующий, и переводчик начал бы накапливать отставание.
Битрейт выбран замером: на 32 кбит/с расшифровка неотличима от сырой, на 16
начинает врать — «вернёмся к консоли» превращается в «к консулу». Отключается
через `LT_COMPRESS_AUDIO=false`.

Предыдущие три реплики уезжают вместе с куском как текст — иначе местоимения в
новом куске не с чем связать. Именно текстом, а не серверной памятью разговора:
у сервиса есть и она, но проверено живым прогоном, что с ней 3,6 минуты встречи
обходятся в 198 722 токена вместо 20 165, потому что весь прошлый звук
перевыставляется в счёт с каждым новым куском.

Список языков, на которых говорят, Gemini не нужен: он определяет язык сам.
Подсказывать пробовали — замер на живой записи улучшения не показал, скорее
наоборот, поэтому в режиме Gemini на вкладке «Языки» задаётся только язык
перевода. У Yandex список остаётся: там он работает белым списком распознавания.

Заодно запросы помечаются `store: false`. Своей памятью мы не пользуемся, а
иначе запись рабочей встречи лежала бы у сервиса 55 дней.

### Что намерено

Замеры на одной и той же записи, от момента «говорящий замолчал» до перевода
на экране:

| Конвейер | Обычно | Четверть дольше | Худшая |
|---|---:|---:|---:|
| Yandex: распознавание + YandexGPT | 2,5 с | 6,8 с | 21,6 с |
| Gemini, куски по 10 с | 2,3 с | 5,6 с | 22,3 с |

По скорости — вровень. Разница в качестве, и она велика.

Расход Gemini: около 20 000 токенов на 3,6 минуты речи, то есть порядка
330 000 на час встречи.

### Ключ Gemini

Кладётся туда же, где остальные настройки. Открытым текстом:

```
LT_GEMINI_KEY=ваш-ключ
```

Лучше — в связку ключей, отдельной записью, чтобы яндексовый ключ остался на
месте и движок можно было переключить обратно:

```bash
security add-generic-password -U -s live-translator-gemini -a "$USER" -w
```

Команда спросит ключ и не покажет его на экране. После этого в настройках
вместо самого ключа пишется способ его достать:

```
LT_GEMINI_KEY_CMD=security find-generic-password -s live-translator-gemini -w
```

Строку `LT_GEMINI_KEY` с открытым ключом при этом надо убрать: значение из
файла главнее команды.

## 8. Сколько это стоит

Главная статья расхода — не распознавание, а модель перевода. Это неочевидно,
поэтому вот разбор настоящего счёта за 20.09.2026: три сессии, 135 фраз,
примерно 36 минут речи.

| Статья | ₽ | Доля |
|---|---:|---:|
| YandexGPT Pro 5, входящие токены | 68,89 | |
| YandexGPT Pro 5, кешированные входящие | 34,94 | |
| YandexGPT Pro 5, исходящие токены | 4,26 | |
| **итого перевод моделью** | **108,09** | **58 %** |
| Синхронное распознавание речи | 69,92 | 38 % |
| Перевод текста Translate (запасной путь) | 6,56 | 4 % |
| **всего** | **184,72** | |

Получается около **0,8 ₽ за фразу**, то есть порядка **200 ₽ за час встречи**.

### Почему модель стоит дороже распознавания

Внутри модели почти всё приходится на входящие токены: 103,83 ₽ против 4,26 ₽
исходящих, отношение 24 к 1. Причина в том, что с каждой фразой заново уезжает
инструкция из восьми правил, весь словарь терминов и несколько предыдущих
реплик — около 1700 знаков служебного текста на 150 знаков полезных. Мы платим
за конверт, а не за письмо.

Отсюда главный рычаг — `LT_MERGE_WORDS`, сколько слов копить перед отправкой.
По умолчанию 25. Вдвое более крупные куски означают вдвое меньше конвертов, и
перевод от этого скорее выигрывает: модель видит за раз больше связной речи.
Плата — задержка, реплика появляется позже. Настройка живёт на вкладке
«Качество» и применяется без перезапуска, так что подобрать её можно прямо на
встрече.

Если значение уже сохранялось в настройках раньше, новое умолчание до вас не
доедет: жмите «Сбросить к значениям по умолчанию» на той же вкладке.

### Распознавание

Тарифицируется блоками по 15 секунд отправленного аудио: порядка **0,16 ₽ за
15 с ≈ 39 ₽ за час** непрерывной речи. Поэтому включён детектор тишины: паузы
уходят на сервер как `silence_chunk` вместо реального звука. На обычной
встрече, где говорят не непрерывно, это заметно снижает объём.

Отложенное распознавание готовых файлов тарифицируется отдельной строкой и
выходит заметно дешевле — разбор записи после встречи стоит копейки.

### Если нужно дешевле

Выключить модель (`--no-llm` или галочка в настройках) — останется обычный
Translate, и час встречи обойдётся примерно в 45 ₽ вместо 200. Перевод при этом
заметно хуже: обычный переводчик не видит контекста и покорно переводит
искажённые распознаванием термины. Это размен, а не улучшение.

### Как понять, за что заплачено

В расшифровке рядом с языком стоит пометка, каким путём переведена фраза:
`` `uz-UZ → модель` `` или `` `uz-UZ → переводчик` ``. Второе означает, что
модель не ответила и включился запасной путь. Если таких строк много — это уже
вопрос надёжности, а не денег.

Актуальные тарифы — в [документации AI Studio](https://aistudio.yandex.ru/docs/ru/speechkit/pricing).

## 9. Словарь терминов

Речь разработчиков — это узбекский с вкраплениями английского и русского:
«deploy qildim», «merge qilamiz», «Spring Boot'da xato». Без подсказки переводчик
обходится с такими словами как с обычными, и смысл фразы плывёт. Словарь в
[glossary.txt](glossary.txt) передаётся в каждый запрос перевода и это чинит.

Формат — одна пара на строку:

```
# комментарий
deploy = деплой
Spring Boot = Spring Boot      # чтобы название не переводили
xatolik = ошибка
```

Ограничения Yandex Translate: **не более 50 пар и 20 000 символов**. Превышение
отвергает весь запрос целиком, поэтому файл проверяется при старте — приложение
не запустится с битым словарём и скажет, в какой строке проблема.

Файл перечитывается на ходу: можно дописать термин прямо во время встречи и
следующая же фраза переведётся с ним. Если в этот момент файл окажется
недописанным, перевод продолжит работать на прошлой версии словаря и скажет об этом.

Пары работают в одну сторону, `uz → ru`. Префикс `!` включает точное совпадение
словоформы, но это возможность нейроглоссариев, а они поддержаны не для всех
языков — для узбекского флаг может быть проигнорирован.

### Как подбирать пары

Не добавляйте термин потому, что перевод непривычен — только потому, что он
**неверен**. Проверено на живом примере: пара `deploy qildik = задеплоили`
сработала, но развалила предложение —

```
без словаря:  Сегодня развернули, тесты прошли          ← смысл верный
со словарём:  Сегодня мы задеплоили пройденные тесты    ← смысл сломан
```

Словарь вмешивается в разбор предложения, и многословные пары с глаголами
склеивают соседние части фразы. Односложные термины и имена собственные
безопасны, глагольные обороты — нет.

Поэтому каждая новая пара проверяется на настоящей фразе:

```bash
java -jar target/live-translator.jar --try="Bugun deploy qildik, testlar o'tdi"
```

Команда переводит фразу дважды, без словаря и с ним, и печатает оба варианта
рядом. Стало хуже — пару убрать.

Другой файл: `--glossary=team-terms.txt`.

## 10. Встреча на нескольких языках

Если на созвоне переходят с языка на язык, перечислите их через запятую:

```bash
./run.sh --device=BlackHole --lang=uz-UZ,ru-RU,en-US
```

Список языков — настройка **распознавания**, а не перевода: он говорит SpeechKit,
из каких языков выбирать, превращая звук в текст. Отключённый язык не пропадает
из распознавания — речь на нём будет разобрана чужой моделью, с искажениями и
неверной меткой. Поэтому отмечайте ровно те языки, которые реально звучат.

SpeechKit определяет язык **для каждой фразы отдельно** и возвращает метку языка
вместе с текстом. Приложение по этой метке решает, что делать дальше:

- фраза на узбекском или английском — переводится на русский;
- фраза на русском — показывается как есть, без обращения к переводчику.

Второе важно не только ради экономии: прогон русского текста через перевод
`ru → ru` портит формулировки на ровном месте.

Язык каждой реплики виден в окне и записывается в лог — вместе с тем, каким
путём получен перевод:

```
**14:52:07** `uz-UZ → модель` Сегодня развернули, тесты прошли
> Bugun deploy qildik, testlar oʻtdi

**14:52:31** `ru-RU` А у меня тесты падают на авторизации
```

Вторая строка без стрелки — русская реплика, её не переводили, поэтому она
записана один раз.

Можно указать `--lang=auto` и отдать выбор сервису целиком, но документация
рекомендует явный список: он работает подсказкой и повышает точность. Перечисляйте
только те языки, которые реально звучат — лишние в списке ухудшают определение.

## 11. Запись звука и разбор после встречи

Кнопка **«записать звук»** в панели окна (или флаг `--record` при запуске) пишет
всё, что слышит устройство, в `logs/audio-<дата>.wav` — 16 кГц, моно, без сжатия.
Час записи занимает около 115 МБ.

Пишется поток до фильтра тишины, то есть в файле остаётся всё, включая паузы.
Так и задумано: файл нужен для разбора, а не для экономии.

Зачем это нужно. Потоковое распознавание идёт вслепую вперёд и не умеет того,
что умеет **отложенное**: разбирать запись целиком и размечать говорящих
(до двух человек). Когда на встрече перебивают друг друга и живой перевод
превращается в кашу, запись позволяет вернуться к этому месту и прогнать его
через отложенное распознавание — там результат заметно лучше.

Если приложение убили принудительно, заголовок WAV останется недописанным, и
проигрыватель покажет нулевую длину. Файл при этом цел — чинится вызовом
`WavRecorder.repair(путь)`.

## 12. Стенд сравнения движков распознавания

Когда перевод плох, спорить можно бесконечно: виновато распознавание, перевод
или сама постановка задачи. Стенд превращает спор в цифры. Одна запись
прогоняется через несколько движков, расшифровки кладутся рядом по времени, и
видно, кто что услышал в одном и том же месте.

```bash
live-translator --bench=~/Documents/LiveTranslator/audio-2026-09-20_11-30-00.wav
```

Получается папка `bench-<дата>` рядом с расшифровками: `report.md` с таблицей и
расшифровками рядом, плюс по файлу на движок — их удобно сравнивать привычным
`diff`.

Полезные ключи (все — `--bench-help`):

| Ключ | Зачем |
|---|---|
| `--reference=эталон.txt` | выправленная вручную расшифровка; без неё WER не считается |
| `--minutes=10` | взять только начало записи: обкатывать настройки дешевле на десяти минутах |
| `--engines=yandex-live,google` | прогнать не все движки, а названные |
| `--chunk-seconds=60` | резать мельче, если вендор не принимает крупный запрос |
| `--no-translate` | только расшифровки, без перевода |

### Эталон

Без эталона стенд показывает мнения: две расшифровки выглядят по-разному, но
какая ближе к сказанному — вопрос вкуса. Поэтому стоит один раз выправить
руками минут десять записи и сохранить в текстовый файл. Тогда в отчёте
появляются две цифры:

- **WER** — доля ошибочных слов;
- **CER** — то же по буквам. Для узбекского он честнее: язык агглютинативный, и
  слово с неверным окончанием пословный счёт записывает в полный промах, хотя
  услышано почти всё.

Эталон должен покрывать тот же отрезок, что и прогон: с `--minutes=10` эталон
тоже нужен на первые десять минут.

### Какие движки есть и что им нужно

Движок без ключа молча пропускается — прогон от этого не срывается.

| Движок | Что это | Ключ |
|---|---|---|
| `yandex-live` | SpeechKit v3 ровно с настройками живого перевода | `YC_API_KEY` |
| `yandex-offline` | та же модель в режиме `FULL_DATA`, для готовых файлов | `YC_API_KEY` |
| `google` | Cloud STT v2, модель Chirp | `LT_GOOGLE_PROJECT` + `LT_GOOGLE_TOKEN_CMD` |
| `azure` | AI Speech, быстрая расшифровка | `LT_AZURE_KEY` + `LT_AZURE_REGION` |
| `azure-terms` | то же, но с подсказкой списком терминов | `LT_AZURE_KEY` + `LT_BENCH_PHRASES` |
| `azure-short` | запасной путь Azure, сам не запускается | `LT_AZURE_KEY` + `LT_AZURE_REGION` |
| `gemini` | дословная расшифровка мультимодальной моделью | `LT_GEMINI_KEY` |
| `gemini-ru` | звук сразу в перевод, без текста посередине | `LT_GEMINI_KEY` |
| `gemini-ru-terms` | то же с подсказкой ожидаемых терминов | `LT_GEMINI_KEY` + `LT_BENCH_PHRASES` |
| `elevenlabs` | Scribe | `LT_ELEVENLABS_KEY` |
| `openai` | Whisper | `LT_OPENAI_KEY` |
| `assemblyai` | отложенное распознавание с разметкой говорящих | `LT_ASSEMBLYAI_KEY` |

### Строка, ради которой стоит смотреть отчёт целиком

`gemini-ru` устроен не как все остальные. Вся наша цепочка — это
«звук → текст → перевод», и средняя стрелка необратимо теряет акустику: дальше
по цепочке «IntelliJ IDEA» можно только угадать по смыслу окружения, потому что
произношения уже нет. Мультимодальная модель этого шага не делает — она слышит
звук и сразу пишет по-русски.

Поэтому WER у неё в отчёте пуст, и это намеренно: эталон выправлен на языке
говорящего, а сравнивать с ним русский текст — мерить одно линейкой другого.
Эту строку читают глазами. Если она заметно понятнее, чем лучшая связка
«движок + перевод», значит, менять надо не движок, а всю схему.

### Азбука настроек Azure

```bash
LT_AZURE_KEY=ключ-ресурса
LT_AZURE_REGION=westeurope        # либо LT_AZURE_RESOURCE=имя-ресурса
LT_AZURE_LOCALES=uz-UZ            # необязательно, по умолчанию первый язык из настроек
```

`LT_AZURE_RESOURCE` нужен, если у ресурса свой поддомен: у Azure встречаются
оба вида адреса, и по ключу не догадаться, какой у вас.

**Регион выбирается не по близости, а по списку.** Быстрая расшифровка есть не
везде: например, в `eastasia` её нет, и движок отвечает `Fast transcription is
not supported in this region`. Ключ привязан к региону, так что переехать можно
только новым ресурсом.

Быструю расшифровку поддерживают, в частности: `southeastasia`, `japaneast`,
`koreacentral`, `centralindia`, `australiaeast`, `northeurope`, `westeurope`,
`uksouth`, `eastus`, `westus`. Полная таблица —
в [документации по регионам](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/regions).

Если менять ресурс не хочется, остаётся запасной путь `--engines=azure-short`:
он работает в любом регионе, но берёт минуту за раз и отдаёт одну реплику на
запрос, поэтому на записи встречи услышит меньше сказанного.

### Подсказка терминами

`azure-terms` — тот же движок, но ему заранее сообщают, какие слова могут
прозвучать. Берутся термины из [glossary.txt](glossary.txt) плюс всё, что
перечислено через запятую в `LT_BENCH_PHRASES`. Словарь составлялся для
перевода и покрывает не всё — в нём есть Kafka и Docker, но нет IntelliJ IDEA,
хотя на встречах его поминают постоянно. Поэтому список можно дополнить, не
трогая словарь:

```bash
LT_BENCH_PHRASES="IntelliJ IDEA,System.out.println,VS Code" live-translator --bench=…
```

Тот же список получает и `gemini-ru-terms`, только не отдельным полем запроса,
а строкой в задании модели.

Проверено 20.09.2026 на узбекской записи: подсказка не изменила расшифровку
вообще, побайтово. Похоже, для `uz-UZ` Azure её игнорирует — для этого языка в
таблице настройки моделей числится только обычный текст. Для языков, где
подсказка работает, рычаг остаётся полезным.

### Тупик, чтобы не возвращаться: LLM Speech

У Azure есть отдельный **LLM Speech API** — языковая модель, слушающая звук, то
же по устройству, что и `gemini-ru`. Для нашей задачи он не годится по двум
причинам сразу, и обе окончательные:

- среди входных языков узбекского нет — только 25 языков, от арабского до
  турецкого;
- среди языков перевода нет русского: `de`, `en`, `es`, `fr`, `it`, `ko`, `ja`,
  `pt`, `zh`.

То же касается готовой страницы субтитров в Speech Studio: это витрина над теми
же API распознавания, она добавляет формат SRT и WebVTT, стабильные
промежуточные результаты и определение языка, но модель под ней та же самая.

### Настройки Gemini

```bash
LT_GEMINI_KEY=ключ
LT_GEMINI_MODEL=gemini-3.5-flash  # необязательно
```

Имена моделей у Gemini меняются часто. Если в ответе не окажется текста, стенд
покажет, что сервис прислал на самом деле, — по этому сообщению видно, какое имя
модели подставить.

Отметки времени Gemini ставит не всегда: на коротком фрагменте он отвечает
сплошным текстом, и тогда весь кусок попадает в отчёт одной репликой. На
сравнение это не влияет, но соседние строки в такой момент выравниваются
грубее, чем у движков со своими временами.

### Размышления модели — главный рычаг скорости и цены

```bash
LT_GEMINI_THINKING=low    # minimal | low | medium | high
```

По умолчанию модель перед ответом размышляет, и на расшифровке это чистый
убыток: задача механическая, услышал и записал, рассуждать не о чем. Замер на
узбекской записи 20.09.2026:

| Вариант | На кусок | Токенов на минуту звука | Термины |
|---|---:|---:|---|
| по умолчанию | ~10 с | ~14 000, из них 74 % на размышления | все |
| `thinking=minimal` | ~1,6 с | ~4 600 (куски по 10 с) | все |

Скорость выросла в несколько раз, расход упал, качество не изменилось: те же
термины, тот же текст. Между `low` и `minimal` разница невелика, но устойчиво в
пользу `minimal`, поэтому он и стоит по умолчанию.

Важно и другое: задержка почти не зависит от длины куска — десятисекундный
обрабатывается столько же, сколько двадцатисекундный. То есть она складывается
из длины куска и постоянных ~4 секунд, и мельчить есть смысл только до предела,
после которого куски начинают резать фразы. Но мельче — дороже: задание
отправляется чаще, и на десятисекундных кусках расход вдвое выше, чем на
двадцатисекундных. Та же история, что с конвертом и письмом в разделе про
стоимость.

Разница между `yandex-live` и `yandex-offline` — самая дешёвая строка отчёта и
часто самая полезная: она показывает, сколько качества стоит сама живость. Если
разрыв велик, чинить надо не движок, а то, что мы просим у него невозможного.

Токен Google живёт час, и хранить его в файле незачем — достаточно научить
приложение получать свежий:

```bash
LT_GOOGLE_PROJECT=мой-проект
LT_GOOGLE_TOKEN_CMD=gcloud auth print-access-token
```

Остальные ключи кладутся туда же, где `YC_API_KEY` — в `.env` или в настройки
пользователя.

### Про деньги

Каждый движок слушает запись целиком, и каждый вендор берёт за это по своему
тарифу. Час записи через шесть движков — шесть оплаченных часов распознавания.
Поэтому настройки обкатываются на `--minutes=5`, и только потом запускается
полный прогон.

## 13. Настройки приложения

**Cmd + ,** открывает окно с тремя вкладками:

- **Языки** — какие языки звучат на встрече и на какой переводить. Набор языков
  применяется сразу: распознавание перезапускается с новыми настройками.
- **Доступ** — смена API-ключа и каталога. Ключ вводится скрытым полем и уходит
  в связку ключей, не в файл. Применяется после перезапуска.
- **Качество** — нарезка речи и перевод: пауза между словами, предел длины
  фразы, порог тишины, склейка, выбор модели. Всё применяется на ходу,
  перезапуск не нужен, рядом кнопка сброса к исходным значениям.
- **Файлы** — где лежат расшифровки и записи; папку можно переназначить,
  рядом кнопка «Открыть в Finder», чтобы не искать путь руками.
- **Звук из созвона** — пошаговая установка и настройка BlackHole.

Всё, что меняется в панели окна, тоже запоминается в `.env`: выбранный источник
звука и галочка «оригинал». Запись звука — намеренное исключение: она всегда
выключена при старте, чтобы случайно не писать встречу целиком.

Ключи настроек в `.env`:

| Ключ | Что задаёт | По умолчанию |
|---|---|---|
| `YC_FOLDER_ID` | каталог Yandex Cloud | спрашивается при первом запуске |
| `YC_API_KEY_CMD` | команда чтения ключа из связки ключей | ставится автоматически |
| `YC_API_KEY` | ключ открытым текстом, если связка ключей не используется | — |
| `LT_DEVICE` | источник звука | `BlackHole` |
| `LT_CHECK_UPDATES` | проверять обновления при запуске | `true` |
| `LT_ENGINE` | чем слушать речь: `gemini` или `yandex` | `gemini` |

## 14. Как устроено

```
AudioCapture      TargetDataLine, 16 кГц / 16 бит / моно, фрагменты по 100 мс
   ↓
SilenceGate       RMS-детектор речи: тишина → silence_chunk, с предзаписью,
                  чтобы не срезать начало фразы
   ↓
RecognizerSession держит распознавание живым: у потока SpeechKit лимит 5 минут
                  и 10 МБ, поэтому поток перезапускается в паузе между фразами;
                  сквозная нумерация фраз, backoff при обрывах, остановка на
                  неисправимых ошибках (неверный ключ, нет прав)
   ↓
SpeechKitStream   gRPC Recognizer/RecognizeStreaming: partial → final →
                  final_refinement
   ↓
PhraseBuffer      копит фразы до осмысленного куска: обрывок в четыре слова
                  переводить бессмысленно, переводчик додумает за вас
   ↓
LlmTranslator     YandexGPT с контекстом последних реплик и словарём терминов;
                  узнаёт искажённые распознаванием названия по окружению.
                  При сбое — обычный Translate v2, встреча не остаётся без текста
   ↓
TranscriptView    ConsoleView + OverlayWindow + SessionLog
```

Стенд сравнения (`--bench`) стоит в стороне от этой цепочки: он берёт готовый
WAV, режет его по тихим местам под предел каждого вендора и гоняет через
`AsrEngine` — общий контракт, за которым может стоять и gRPC, и чужой REST.
Нарезку, смещение времён, замер времени и разбор ошибок держит `Bench`, поэтому
новый движок стоит одного класса и никак не задевает живой перевод.

Фраза сначала появляется на исходном языке (`… текст`), затем строка заменяется
переводом. В панели сверху: выбор источника звука (переключается на ходу, без
перезапуска), кнопка записи с таймером, галочка «оригинал» — она оставляет под
переводом исходную фразу, — и справа строка состояния.

## 15. Что доделать, когда поживёте с этим неделю

- **Пополнять словарь по ходу дела.** Держите [glossary.txt](glossary.txt) открытым
  на первых встречах: каждая фраза, где перевод соврал на термине, — это одна
  новая строка. Лимит в 50 пар заставляет оставлять только то, что реально звучит.
- **Дообучение на своей лексике.** У SpeechKit для `uz-UZ` доступна настройка
  модели списком слов (Custom Speech, plain text).
- **Двусторонний режим:** ваш русский → узбекский синтез через TTS v3, чтобы
  отвечать команде.
- **Горячая клавиша паузы**, чтобы не гнать в облако приватные разговоры.
